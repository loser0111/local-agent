# Spec Delta

## Purpose

为桌面端前端定义可度量的视觉呈现规范：文本对比度下限、排版度量（字号层级、行高比值、正文行宽区间）与界面信息密度，使主题与排版类改动有可验收的基线，而不是靠目视判断。

## ADDED Requirements

### Requirement: 文本对比度下限

界面文本 MUST 在与**实际承载背景**的组合下达到 WCAG AA：常规字重的非大号文本对比度 SHALL 不低于 4.5:1。对比度 MUST 按 WCAG 相对亮度公式计算后判定，不得以目视观感代替。

#### Scenario: 浅色主题次要文本在三档背景上达标

- **GIVEN** 浅色主题，正文背景 `bg-primary` `#ffffff`、`bg-secondary` `#f4f4f8`、`bg-tertiary` `#e6e6ef`
- **WHEN** 次要文本（`text-muted`）渲染在以上任一背景上
- **THEN** 三档背景的对比度均不低于 4.5:1

#### Scenario: 深色主题正文与次要文本达标

- **GIVEN** 深色主题，正文背景 `bg-primary` `#282a36` 与 `bg-secondary` `#21222c`
- **WHEN** 正文（`text-primary`）、次要文本（`text-secondary`、`text-muted`）分别渲染在这两档背景上
- **THEN** 全部组合的对比度均不低于 4.5:1

#### Scenario: 语义色文字落在凸起表面仍达标

- **GIVEN** 浅色主题，`bg-tertiary` `#e6e6ef` 作为卡片/输入框底色
- **WHEN** 成功/警告/错误等语义色以文字形式渲染在该底色上
- **THEN** 对比度不低于 4.5:1，否则该语义色 MUST 改用专供文字使用的深色变体

### Requirement: 次要文本的承载表面限制

次要文本 token（`text-muted`）SHALL 只用于 `bg-primary` 与 `bg-secondary` 之上。当需要在 `bg-tertiary` 这类凸起表面上表达次要语义时，MUST 改用 `text-secondary`，因为提亮/加深 `text-muted` 至该表面达标会使其与 `text-secondary` 的层级塌陷。

#### Scenario: 深色主题凸起表面上的说明文字

- **GIVEN** 深色主题，`bg-tertiary` `#44475a`（按钮、输入框、无边框卡片底色）
- **WHEN** 需要在该表面上放一段说明性文字
- **THEN** 使用 `text-secondary`（该表面 5.11:1），不使用 `text-muted`（该表面 4.01:1）

#### Scenario: 次要文本与主文本的层级不被抹平

- **GIVEN** 任意主题
- **WHEN** 同一屏幕内同时出现 `text-primary`、`text-secondary`、`text-muted`
- **THEN** 三者在各自背景上的对比度保持单调递增的层级关系，相邻两级差距可辨识

### Requirement: 正文排版度量

聊天正文 SHALL 使用正文字号层级（14px 基准）而不是次级字号；行高 MUST 以无单位倍数表达并落在 1.5–1.75 区间；行高 MUST 随字号基准等比缩放，不得使用固定像素增量。

#### Scenario: 默认基准下的正文取值

- **GIVEN** 字号基准为默认 14px
- **WHEN** 渲染聊天正文
- **THEN** 字号为 14px，行高为 1.7 倍（约 24px）

#### Scenario: 字号基准改变后行高等比跟随

- **GIVEN** 用户通过设置页把字号基准调大或调小
- **WHEN** 正文重新渲染
- **THEN** 行高按倍数等比放大或缩小，比值仍落在 1.5–1.75 区间

### Requirement: 正文列宽自适应与上限

正文列宽 SHALL 随**容器**宽度自适应伸缩，以充分利用可用空间；同时 MUST 设固定上限，使超宽窗口下行长不至于无限增长。列宽 MUST 相对容器解析而不是视口，保证侧边栏或右侧面板展开时列宽同步收窄而不溢出容器。

#### Scenario: 常规窗口下按容器比例伸缩

- **GIVEN** 聊天面板可用宽度在 800–1200px 之间
- **WHEN** 渲染消息列
- **THEN** 列宽占容器宽度的固定比例（约 92%），两侧留白对称且不出现大片空白

#### Scenario: 超宽窗口下达到上限后不再增长

- **GIVEN** 窗口宽度大幅增加，聊天面板可用宽度超过列宽上限
- **WHEN** 继续拉宽窗口
- **THEN** 列宽停止增长并保持在上限值，消息列在容器内水平居中

#### Scenario: 侧栏或右侧面板展开时不溢出

- **GIVEN** 列宽已按容器比例计算
- **WHEN** 左侧栏展开或右侧面板占用空间，导致容器可用宽度变小
- **THEN** 列宽随之收窄，不出现横向滚动，也不溢出容器边界

#### Scenario: 代码块不受列宽上限截断

- **GIVEN** 正文中出现超长的代码块
- **WHEN** 渲染该消息
- **THEN** 代码块按自身溢出策略横向滚动，内容不被列宽上限裁掉

### Requirement: 状态表达的冗余禁止

会话列表项 SHALL 用视觉标记（状态圆点、选中高亮）表达常态状态，MUST NOT 在每行重复渲染状态词；仅非常态（运行中、待应答）MAY 以文字芯片呈现，且同一状态 MUST NOT 同时以文字与圆点重复表达。

#### Scenario: 常态会话行不出现状态词

- **GIVEN** 一条状态为活跃（active）的会话
- **WHEN** 渲染该列表项
- **THEN** 该行只显示会话标题与相对时间，状态由圆点表达，不出现「活跃」字样

#### Scenario: 非常态会话行保留文字芯片

- **GIVEN** 一条正在运行或待应答的会话
- **WHEN** 渲染该列表项
- **THEN** 显示「运行中」或「待应答」芯片，且不再叠加表达同一状态的圆点

### Requirement: 占位符与说明文案分离

输入框 placeholder SHALL 只承载「这里输入什么」的单一提示，MUST NOT 承载快捷键、命令语法等多条说明。此类说明 MUST 放在输入框之外的独立位置，字号 SHALL 不小于 12px，并满足文本对比度下限。

#### Scenario: 输入框初始态只显示单一提示

- **GIVEN** 聊天输入框为空且未聚焦
- **WHEN** 渲染输入区
- **THEN** placeholder 为一条简短提示，不含快捷键与命令说明

#### Scenario: 快捷键说明常驻且可读

- **GIVEN** 聊天输入区已渲染
- **WHEN** 用户查看输入框周边
- **THEN** 快捷键与命令语法说明在输入框外侧独立呈现，字号不小于 12px，且对比度达到 4.5:1
